# 可扩展语言资源

首版提供 `zh-CN`（默认）和 `en`；不是业务页面内硬编码的双语言开关。

- `resources/locales/registry.json`：稳定locale ID、用户可见本名、字体族、默认与回退locale。
- 各 `ID.json`：以稳定语义键组织界面、设置、状态、错误；SCPI关键字/仪表型号/单位保留原文。
- `scripts/generate_i18n.py`：检查重复locale、未知key、命名占位符集合一致性，并生成不可变C++资源及中文字符集合。缺译允许使用fallback（当前en）；未知key最后显示key，便于发现问题。
- `core/i18n.*`：locale注册查询、查找/回退、`{value}`等命名占位符替换；不以if(中文)/else英文分支驱动业务页面。
- `main/ui.cpp`：语义key渲染和独立FontFamily映射。语言菜单遍历注册表，可滚动，不限定两个选项。
- `fonts/panel_cjk_14/20/24.c`：Noto Sans SC OFL字体，450字重、4bpp，含全部当前资源汉字和语言本名。大号数字独立使用Montserrat48/32，减少CJK字体存储。字体位图位于rodata/PSRAM映射，非每次切换重分配整套字库。
- 板上独立NVS namespace `th2822panel` 的 `locale` key保存选择；不擦除原NVS。NVS无法打开/提交时明确报错，语言仍可临时切换。启动无记录则中文；未知保存ID回退默认。

## 增加一种语言

1. 在registry中加入稳定BCP47风格ID、语言本名和字体族；新增同名JSON，使用en中语义键。
2. 运行 `python3 scripts/generate_i18n.py` 和 `python3 scripts/check_locales.py`。缺译回退英文；占位符缺失/拼写不匹配会失败。
3. 若现有字体族不覆盖新脚本，增加相应许可字体及FontFamily映射（仅字体层），更新字体子集生成。业务页面无需改动。
4. 运行主机i18n测试及同一LVGL模拟器，检查最长文本、按钮、菜单和错误行。首版仅验收横排LTR布局；RTL/复杂脚本需要开启并验收LVGL双向/塑形支持，不能仅添加翻译就声称支持。
5. 实机切换、重启，核对NVS持久化与堆无持续增长。

## 可重现字体工具

原字体：Google Fonts官方 `ofl/notosanssc/NotoSansSC[wght].ttf`，OFL.txt保存在fonts中。FontTools4.60.1在项目隔离环境 `tools/font-env`；LVGL官方lv_font_conv1.5.3及npm锁文件在 `tools/font-builder`。安装npm时使用`--ignore-scripts`。运行`python3 scripts/build_fonts.py`重建；普通固件构建使用已提交的C子集，不需要再下载字体或安装Node。

运行测试：

```sh
python3 scripts/check_locales.py
cmake -S tests -B build-host
cmake --build build-host
ctest --test-dir build-host --output-on-failure
./build-preview/panel_preview --capture docs/screenshots/v0.3-zh zh-CN
./build-preview/panel_preview --capture docs/screenshots/v0.3-en en
```

字体首次准备（普通固件构建不需要）：按`fonts/SOURCE.json`的官方URL取得字体，保存为`fonts/NotoSansSC.ttf`并校验SHA256；创建隔离Python环境安装FontTools==4.60.1，在tools/font-builder运行`npm ci --ignore-scripts`，然后运行build_fonts.py。子集C文件可直接用于离线构建。
