# TH2822E 原生 REC 直连测试（2026-10-07）

## 结论及范围

对象：TH2822E Handheld LCR Meter,VER4.5.2307,SNQ495260477，CP2102 10c4:ea60 / 0001，直连 /dev/cu.usbserial-0001，9600/8N1，LF。用户确认测试端开路。初始 C/D、120 Hz、0.3 V、PAL、TOL OFF、REC ON。

**不能把 REC 的 MAX/MIN/AVER/PRES 查询当作无副作用的后台读操作。** 它们会选择仪表显示状态并发提示音；同一 AVG 状态重复 AVERage? 也会响。0.4.1–0.4.3 循环轮询三项统计的实现会持续触发这种行为。此前将滴声仅解释为原生记录存入提示的说法不充分，已依据直连实测纠正。

用户已验收 0.4.3 的自动进入统计页、顶部布局。用户随后明确要求先直连测试，弄清后再改程序。自该要求起未修改固件源码、未重新刷写。开发板当前仍为 0.4.3，其原生 REC 后台轮询问题尚未修复；不把它作为 REC 功能验收通过的版本。

## 方法

同一串口保持打开，精确校验身份；一次只发指定命令，响应后停发并由用户观察声音和 LCD。查询间隔至少 1.2 秒，不采用开发板高频轮询。仅允许手册列出的查询及 REC ON/OFF 的诊断脚本，本轮实际没有发送 REC ON/OFF、测量参数、校准或永久设置。记录期间没有后台查询线程。

## 数据含义

1. PRESent? 自身的 ----- 不等于这个功能完全不可用：它选择记录显示后，FETCH 能读到变化主副值。0.4.3 暂时隐藏当前值是保守回避，后续可按经过验证的显示状态重新设计。
2. MIN 显示下 FETCH 返回最小值，并非当前测量；不能把任意 REC 状态下的 FETCH 都标成实时值。
3. AVG 显示下 FETCH 两次返回先前 MAX 数值，与 AVERage? 给出的平均值不同。因此本机 AVG 不能通过 FETCH 代读；这里记录的是本次具体固件/状态的异常，不宣称全系列都有同一缺陷。
4. 原生 MAX/MIN/AVG 的副参数字段均为零，而记录显示 FETCH 的 D 明显非零。这些零是仪表返回，不是触摸屏漏算。不用本地算法替补；是否存在有效副统计以及数值准确性，仍需稳定元件、不同模式的进一步对照，开路数据不能验证测量精度。
5. 单独重复同一 AVG 查询仍响，故“只轮询选中的统计项”也不能直接视为静音方案。

## 基于本轮测试的方案（0.4.4 已实现，见 REC_TIMING.md）

- 停止后台轮流读取 MAX/MIN/AVG/PRES。
- 若要求安静并保留原生三项统计，用明确的按需读回/手动刷新；展示为最近一次读回结果，避免假装三项都在实时更新。
- 普通记录显示只在进入时选择 PRES 一次，然后用 FETCH 更新主副值；切换时那一次提示音属于已观察的命令效果。
- 平均值按需用 AVERage? 正确读回，不能用 FETCH 伪装平均值；没有验证到同时满足“三项原生持续刷新、安静、数值正确”的已公开命令路径。
- 不发送猜测的蜂鸣静音命令，不改仪表永久设置。
- 0.4.4 已据此实现四页签和手动更新；原生数值准确性仍需稳定元件对照。
